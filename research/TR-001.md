# Technical Report 001

## Kernellum Compiler v0.1: Constraint-Driven Generation of a Quantized Neural Accelerator

**Sushanth Dasari — Kernellum Research**  
September 2026

### Abstract

Kernellum Compiler v0.1 is a compact research prototype for model-to-accelerator generation. The system trains a small neural workload, constructs an integer-only representation, evaluates candidate MAC-lane configurations against a latency constraint, emits FPGA-oriented SystemVerilog and memory initialization files, and verifies the generated design against a separate cycle-accurate software model. On a 64→32→16→10 handwritten-digit classifier, the floating-point model reaches 96.22% held-out accuracy and the generated INT8 execution model reaches 96.44%. Their predictions agree on 99.78% of the 450 held-out samples. A cycle-level model matching the RTL scheduling semantics reproduces the vectorized INT8 output tensor exactly for all 450 samples. Under an assumed 100 MHz clock and a ≤10 µs modeled core-latency constraint, the search selects four parallel MAC lanes, corresponding to 680 modeled compute cycles or 6.8 µs. No post-place-and-route, physical power, FPGA resource, or measured timing result is claimed in v0.1.

## 1. Motivation

Specialized AI accelerators expose a hardware–software co-design problem: compute parallelism, numerical precision, memory organization and scheduling must be selected together for a target workload and deployment constraint. Kernellum investigates whether increasingly large parts of this mapping process can be automated and made reproducible.

v0.1 intentionally uses a small workload. The goal is not to demonstrate a competitive NPU; it is to exercise an end-to-end research path from trained model to quantized execution, architecture choice, generated RTL and verification.

## 2. Demonstration workload

- Dataset: `sklearn.datasets.load_digits`
- Input: 64 normalized image features
- Network: 64 → 32 → 16 → 10
- Hidden activation: ReLU
- Test split: 25%, stratified, random state 42
- MLP seed: 11
- Test samples: 450

The trained floating-point model reaches **96.22%** test accuracy.

## 3. Integer execution model

Weights are symmetrically quantized to signed INT8. Activations use calibrated per-layer symmetric scales. Biases are converted to 32-bit accumulator units. Each layer uses a fixed-point requantization multiplier and a 30-bit right shift, followed by saturation to signed INT8. Hidden layers apply ReLU.

The resulting integer model reaches **96.44%** held-out accuracy. Float and INT8 predictions agree on **99.78%** of samples.

## 4. Architecture search

v0.1 searches a deliberately small design space: `{1, 2, 4, 8, 16}` parallel MAC lanes. The objective is the smallest lane count satisfying a ≤10 µs modeled core latency at an assumed 100 MHz clock.

| MAC lanes | Core cycles | Modeled latency | Meets target |
|---:|---:|---:|:---:|
| 1 | 2720 | 27.2 µs | no |
| 2 | 1360 | 13.6 µs | no |
| 4 | 680 | 6.8 µs | yes |
| 8 | 340 | 3.4 µs | yes |
| 16 | 170 | 1.7 µs | yes |

The selected design therefore uses **4 MAC lanes**.

The cycle count is computed from layer dimensions and lane width. For four lanes:

- layer 1: `32 × (64 / 4) = 512` cycles
- layer 2: `16 × (32 / 4) = 128` cycles
- layer 3: `10 × (16 / 4) = 40` cycles
- total core compute: **680 cycles**

The 6.8 µs figure is a model at 100 MHz, not a measured FPGA result.

## 5. Generated hardware

The generator emits:

- `kernellum_mlp_accel.sv` — signed-INT8 inference datapath and controller
- `kernellum_demo_top.sv` — small FPGA-oriented demonstration wrapper
- `tb_kernellum_mlp_accel.sv` — end-to-end testbench
- weight and bias HEX memories
- 32 held-out golden input/output vectors
- a machine-readable manifest

The accelerator uses signed INT8 activations/weights, 32-bit accumulation, fixed-point requantization, saturation and ReLU for hidden layers.

## 6. Verification

Two software implementations are intentionally kept separate:

1. a vectorized INT8 reference model;
2. a cycle-level model reproducing the generated hardware's output-neuron scheduling, lane grouping, accumulation, requantization and layer transitions.

Across all **450 held-out samples**, their output tensors match exactly.

The generated HDL testbench additionally contains 32 held-out golden cases. The repository CI is configured to compile and execute this testbench with Icarus Verilog and then run Yosys synthesis.

## 7. Limitations

v0.1 does **not** yet establish:

- FPGA timing closure;
- LUT, FF, DSP or BRAM utilization;
- measured board power;
- measured end-to-end latency;
- support for arbitrary ONNX graphs;
- transformer operators;
- competitive results against existing accelerator compilers.

These are explicit next milestones rather than hidden assumptions.

## 8. Next milestone

The next technical milestone is a real FPGA implementation with a named device and reproducible post-place-and-route evidence. In parallel, the compiler should move from a fixed demonstration topology toward an operator-level hardware IR and automatic graph lowering.

Longer term, Kernellum aims to investigate workload-specific accelerator generation under multi-objective latency, area, memory and energy constraints.
