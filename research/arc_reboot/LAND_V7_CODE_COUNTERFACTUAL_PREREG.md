# ARC Reboot — Independent LLM Code-Hypothesis Counterfactual Test

Status: PREREGISTERED BEFORE INGESTING OR SCORING THE RELEASED V7 CANDIDATE TRACES.

## Source

Independent hypothesis generator:
- Johan Land, ARC-AGI solver V7 public run
- solver repository pinned separately
- public ARC-AGI-2 evaluation run released on Kaggle and cited by the paper as containing raw prompts, responses, reasoning traces, intermediate artifacts, and judge transcripts.

The candidate generator, models, prompts, search procedure, and judges were developed independently of this project.

## Scientific question

Do label-free counterfactual execution signatures contain useful information for selecting among **real LLM-generated executable hypotheses** that all fit the ARC demonstrations?

This is a stronger transfer test than the prior DSL attempts because candidate programs are generated by frontier LLM search rather than by local AST mutation or a hand-enumerated DSL.

## Candidate extraction

For every public-evaluation task/test case represented in the released V7 logs:

1. extract codegen solver candidates only;
2. require a complete executable `solver(grid)` function;
3. require Land's own training verification status to be PASS, or independently reverify exact correctness on every demonstration if verification metadata is absent;
4. deduplicate byte-identical code before execution;
5. exclude judge/synthesis outputs from the candidate pool;
6. exclude candidates that cannot execute under the frozen sandbox. Test-answer leakage is NOT used to filter the primary pool because detecting it requires the held-out answer. After the frozen primary is scored, perform a contamination audit for literal answer embedding or equivalent hard-coding and report a sensitivity analysis excluding contaminated cases.

The original Land candidate order, modality label, model identity, vote count, judge score, and test correctness are stored for later analysis but are **not available to the primary selector**.

## Safe execution

Candidate code is arbitrary generated code and is executed only in an isolated container/process sandbox with:
- no network;
- read-only source/data mount;
- no secrets;
- per-call wall-clock timeout;
- CPU and memory limits;
- output restricted to one rectangular ARC grid with integer colors 0–9 and dimensions <=30x30.

Timeout, exception, invalid output, or policy-violating filesystem/network behavior is treated as invalid execution, never as a negative correctness label.

## Frozen probe construction

From demonstration inputs only:

Primary mixed set, deterministic seed 20261028, cap 24 unique probes:
- D4 rotations/reflections;
- permutations of nonzero colors while preserving zero;
- cyclic row/column rolls.

Secondary D4-only set, cap 12.

No public test input, test answer, Land judge score, candidate correctness flag, or final result is used to generate probes.

## Semantic classes

For a candidate h, define its probe signature as the sequence of valid/invalid output grids on the primary probes.

Candidates with identical complete signatures are one semantic class.

Canonical class representative:
1. shortest normalized source length;
2. then SHA256 of normalized source.

The source-length criterion is a deterministic representative tie-break only and is not a claimed simplicity prior.

## Primary selectors

B_cls — duplicate-invariant semantic-class plurality on the actual ARC test input:
- one vote per semantic class;
- vote is the canonical representative's test prediction.

D — counterfactual medoid:
- centrality of class c is mean pairwise agreement with all valid semantic classes over primary probes;
- select the class with maximal centrality;
- ties by canonical representative rule.

W — centrality-weighted predictive vote:
- each class votes for its actual test prediction with weight equal to its primary-probe centrality.

Secondary:
- D4 versions of D/W;
- raw candidate plurality, which is duplicate-sensitive.

## External comparison only

Land's own holistic judge selection, candidate judge scores, model identity, modality, and vote count are reported after the frozen selectors are evaluated.

They cannot influence D/W/B_cls.

## Usable case

A task/test case is usable when:
- >=3 verified executable candidates;
- >=3 primary semantic classes;
- >=2 distinct valid candidate predictions on the actual test input.

Cases where no candidate predicts the correct answer are retained for overall selector accuracy but reported separately as oracle-negative cases.

## Endpoints

Primary practical endpoint:
- task/test-case top-1 accuracy of D versus B_cls.

Secondary:
- W versus B_cls;
- D4-D and D4-W versus B_cls;
- pass@2;
- oracle-positive subset;
- minority-correct cases where the correct grid has <50% semantic-class support;
- comparison to Land's released vote/judge choices where reconstructable.

Bootstrap confidence intervals resample ARC task IDs, keeping multiple test cases of one task together.

## Frozen survival rule

The counterfactual selector transfers as a practical method only if all hold:

1. >=30 usable task/test cases;
2. >=20 distinct ARC tasks;
3. D improves top-1 over B_cls by >=3 percentage points;
4. task-bootstrap 95% CI for D-B_cls is not entirely below zero;
5. D improves at least 5 distinct task IDs;
6. D is non-inferior on oracle-positive cases;
7. D yields positive gain on minority-correct cases.

W/D4 are secondary and cannot rescue a failed D primary.

## Mechanism endpoint

Regardless of query-selection success, measure whether class centrality predicts candidate correctness on the actual test query:

- point-biserial/Spearman association between class centrality and exact test correctness within usable cases;
- case-macro association;
- AUC for centrality as an unlabeled correctness score.

This endpoint is explicitly descriptive if D primary fails.

## Interpretation discipline

PASS:
counterfactual behavior transfers from synthetic executable version spaces to independently generated LLM program hypotheses and improves real ARC query selection.

PRIMARY FAIL + POSITIVE MECHANISM:
counterfactual centrality tracks hypothesis quality but should not be treated as a query-level decision rule.

NO ASSOCIATION:
the Stage B signal is candidate-generator-specific and the centrality mechanism is substantially weakened.

COVERAGE FAIL:
the released trace corpus contains too few verified, semantically distinct code hypotheses to adjudicate the claim.


## Frozen probe sampling implementation detail

For each task/test case, construct the candidate probe list in this order:
1. all unique D4 transforms of every demonstration input;
2. three deterministic nonzero-color permutations per demonstration input, preserving zero;
3. row and column cyclic rolls by +1 and -1.

Canonical-grid deduplicate the full list, then deterministically shuffle using seed 20261028 mixed with SHA256(task_id:test_index), and keep the first 24. D4-only uses canonical deduplication of D4 transforms in generation order and keeps the first 12.

## Frozen invalid-execution centrality rule

For each probe:
- if a class representative returns a valid grid, its agreement contribution is the fraction of **valid-output classes** on that probe that return exactly the same grid;
- if the representative is invalid/timeout/exception on that probe, its agreement contribution is exactly 0;
- if no class returns a valid output on a probe, every class receives 0 for that probe.

Class centrality is the arithmetic mean across all frozen probes, including zero-contribution invalid probes. Thus crashes cannot gain agreement by sharing an invalid sentinel.
